# Executable gameplay-quality interfaces

The module ownership and exact station fields are in QUALITY-CONTRACT.md. These exports are exercised by production code and quality-station* tests.

- shared/station-contract.mjs: STATION_TASK_VERSION=1, STATION_TASK_KINDS, isStationTask(task), STATION_INPUT_FIELDS.
- shared/station-challenges.mjs: createStationChallenge({kind,seed}), validateStationChallenge(c), projectStationChallenge(c), applyStationInput(c,{interactionId,value}), nextStationInput(c), stationComplete(c), stationProgress(c). State is {version:1,kind,puzzle,progress:{values:string[]}}. Applying returns immutable {accepted,error?,challenge,completed}; invalid data never advances progress. Projection clones owner-permitted clues. See QUALITY-CONTRACT.md for each exact interaction/value.
- engine.createMatch({...existing,tactical:true,stationTasks:true,map:{id:'beacon',version:2}}) creates match5. Without explicit station opt-in constructors retain prior semantics; native normal transport opts in through stationTasksMode. loadConfig enables this normal default. New match5 tasks are {id,label,roomId,completed,kind:'station',challenge}. Root/store validate all challenge versions and completion consistency.
- server/features/tasks retains its service registration and adds stationTask beside relayTask. Structured taskInteract {taskId,interactionId,value} is proposed through authenticated room action API with its normal unique id. task is an open-only accepted action for stationTask. Never replace server progress with a client solved flag.
- Public owner self.tasks includes projectStationChallenge only for that owner. Other keepers and spectators receive no task puzzles. Validated task_progress/task_opened events stay owner-private during live play; ended replay authorization is unchanged.
- server/ai/world.mjs derives nextStationInput from the safe view and submits normal engine actions. Use this capability path for future strategic goals; no provider calls per frame or alternate state mutation.
- public/features/tasks/station.mjs createStationPuzzle({task,onSubmit,onClose,id}) exposes node, update(task,{pending,connected}), dispose and its existing panel contract. createTaskPuzzle delegates new station kinds; old three local puzzle paths stay for old saves. onSubmit({interactionId,value}) waits for current safe-view confirmation. Caller owns task ID and stale-context checks.
- shared/maps/index.mjs getMap({id,version}) uses exact immutable identity, getMap(string) latest registered map, getMap(undefined) original Beacon1. MAP_CATALOG lists latest Beacon2 and Annex1. Per-room taskKinds and typed art props augment existing geometry/fixtures, not mutable global selection.
- engine.prepareNavigation(references) accepts at most8 registered exact/string references and returns {id,version,warmed} entries, warming only public geometry before listening. It never constructs matches or mutates identity/AI state.
- public/world/movement.mjs MotionTrack: constructor({interpolationMs,predictionMs,mapResolver}), update(game,at), at(id,time,reduced), setIntent(input,at), clear. Default ActorSamples now delegates real world views to it; legacy Cartesian test fixtures retain their mathematical API. createWorldScene uses this default and snapshot-anchored ObservedCamera. Missing actors, older versions, doors, phase, map and life changes revoke stale presentation.

Integrated example: create a normal room via POST /api/rooms; select its versioned map in the lobby; start; use game.interactions' exact task hint near a station. Open with task, then submit each taskInteract with a fresh action id. Read authoritative self.tasks.challenge.progress after every acknowledgment. Persist/reconnect with the same HttpOnly seat cookie. A repeated action id returns its original receipt, not a second progress step. Complete the watch and request replay only through its existing authorized ended route. tests/quality-station-http.test.mjs executes this path with real HTTP and a restart; scripts/world-browser-check.mjs uses actual station controls.
