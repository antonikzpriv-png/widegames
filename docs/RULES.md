# Lantern Wake engine rules and integration notes

Integration clarification: a keeper may submit at most2,048 well-formed unique request IDs per match, including rule denials. Old IDs are retained, never evicted into eligibility for a second mutation. After the cap, new IDs are explicitly rejected and retained duplicates stay inert. AI-prefixed IDs and browser UUIDs use the same bounded envelope. The transport persists engine-produced denial/deadline state before returning an error.

The five named exports live in `server/engine/index.mjs`: `createMatch`, `applyAction`, `tick`, `getPlayerView`, `getReplay`. No dependency installation is required. `createMatch` accepts rule overrides directly as `config` (transport passes `config.rules` here), using the exact shared default keys. Internal serializable state has `schemaVersion:1`, `players`, `requests`, `replay`, timestamps, and rules; transport must keep all of it private. Only engine views go to clients and AI. No contract additions are required.

A match begins roaming with six keepers, exactly five crew and one saboteur. The role and room distribution use a cryptographic random secret in production; explicit test seeds reproduce state. Public match IDs do not influence roles. Human mode reserves p1; spectator mode has no human. The secret is never retained.

Movement follows a single map edge. Crew complete their own assigned relay tasks in the task's room. Completed tasks cannot be repeated. Three tasks per crew are assigned by default. On death/ejection, unfinished crew tasks are redistributed round-robin to living crew, preserving task IDs and total task count; completed tasks remain counted. Dead keepers cannot act or vote. This avoids requiring an absent/dead human to finish tasks.

Initial movement/task cooldowns are zero. Initial elimination cooldown is 18 seconds, sabotage 65 seconds, emergency bell 35 seconds. Subsequent movement/task/elimination/sabotage cooldowns are 1.2/4/22/65 seconds. Sabotage can be started remotely and creates a public critical failure in Engine. Two distinct living crew in Engine must each repair once before its 75-second deadline. The saboteur cannot repair. A repaired critical failure remains visible with active:false until another sabotage replaces it.

The saboteur can eliminate a living crew member in the same room. A body ID is `body-<victimId>`. Report requires a locally visible, unreported body. Reporting clears all currently unreported bodies. The bridge emergency bell requires its cooldown, one remaining emergency use (one per keeper by default), and no active critical failure. A report remains possible during critical failure.

Meetings freeze roaming actions. Action cooldowns and the critical countdown continue in wall-clock time. Meeting positions stay where they were; other players' positions remain local observations. Discussion lasts 30 seconds, then voting lasts 20 seconds. Each living keeper can send three messages of at most 280 characters; surrounding whitespace is trimmed, control characters rejected. Each living keeper can vote once for a living keeper (including self) or skip. No early tally occurs. The unique plurality wins: skip plurality, any tie including skip, or no votes means no ejection. Missing voters abstain. Targets stay hidden until tally. The eligible voter list is fixed at the meeting start. After tally the next roaming deadline is four minutes away, and all emergency bell cooldowns are at least 35 seconds from tally. Reports have no bell cooldown.

A missed four-minute roaming deadline calls an automatic meeting, even if browsers are disconnected. Tick processes all elapsed deadlines at their original times, so a delayed call does not extend discussion/voting/critical time. At an exact deadline the transition occurs before any submitted action. Critical failure has precedence at simultaneous deadlines, then maximum duration, then phase transitions. A 15-minute maximum duration pauses the match with a public paused event and no winner; there is no automatic resume action in v1. Paused matches remain available for inspection, replay remains locked, and transports must label the pause truthfully.

Crew win by completing all tasks or ejecting the saboteur. The saboteur wins at living parity or a missed critical deadline. No model or timeout declares a synthetic winner. Ended matches reject further actions.

Safe view keys exactly match CONTRACT.md. `availableActions` contains type names validated against present phase/location/cooldowns. Spectators see public physical positions but no self/private tasks/roles before the end. Players see only local positions, their own role/tasks, aggregate task progress, and public status. No human/AI flag, hidden task assignments, request IDs, rules, seed, repairer list, replay, or pause internals leak into views. Roles appear on `players` only when ended.

The frozen view has no bodies list. A locally visible unreported body appears as an event `{id:bodyId,type:'body',bodyId,playerId,roomId,at}`; AI/UI use `bodyId` to report it. Eyewitnesses receive `{id,type:'witness',at,playerId:eliminatorId,targetId,roomId}` only if alive and physically present at the elimination. Public eliminated events expose only victim ID; no killer or kill room. Task/move/sabotage actor attribution is absent from public events. Dialogue is explicitly untrusted text and must render via textContent. Vote result events contain tally targets. Each view has at most 256 timeline entries. Views and replay are defensive copies.

`getReplay` returns null before ended (including paused), then an array of fully attributed events including actions, task transfers, outcome, and final role reveal. To bound persistent memory, it retains the latest 12,000 replay records; the final role reveal is always included. Public events retain 256 records. Requests retain the latest 256 valid envelopes per actor, including rule denials. An identical retained request repeats its original result without executing; different contents under the same ID reject with REQUEST_CONFLICT. After eviction a request ID can be reused; clients must always create new IDs. This window survives JSON persistence. Malformed envelopes are safely denied and never persisted. Accepted wait and persisted rule denials are actual state changes and increment version; a no-op tick or duplicate does not. A late action can also include events from automatic deadline processing. Transport must persist returned state even on denial, and must not expose internal state or raw replay before ended.

Task IDs are opaque deterministic hashes under the private seed; their sequence never reveals which preceding keeper has the hidden role. Untallied ballots stay hidden even when a match pauses during voting. The internal tally marker is excluded from the exact shared meeting shape.
