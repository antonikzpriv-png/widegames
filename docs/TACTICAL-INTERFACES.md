# Tactical integration interfaces

These are packaged executable interfaces in the existing Node ESM/native HTTP/ws/plain-browser app. Read TACTICAL-CONTRACT.md for ownership and TACTICAL-RULES.md for semantics. Group2's task/goal/lobby/death-ability/panel/replay modules remain their integration points; this phase does not require an unmerged branch or replace them.

## Immutable map registry

shared/maps/index.mjs exports DEFAULT_MAP_ID, MAP_CATALOG, getMap(reference?), mapFor(stateOrView), deepFreeze(value). The catalogue contains public {id,version,name,description,theme}. getMap accepts an ID string, exact {id,version}, or absent reference for the original Beacon. Unknown identity/version throws; it does not silently substitute. mapFor reads value.map.

The frozen descriptor is {id,version,name,description,theme,roomLayout,geometry,fixtures}. roomLayout contains actual room IDs/names/neighbors/descriptions/display positions. geometry exports the original shared/world.mjs function surface plus ROOM_LAYOUT, WORLD_VIEWPOINT, WORLD_SPAWN_ROOM and fixtures. fixtures contains doors, vents, repairs, devices and cameras in their existing typed shapes. New geometry factories/caches are map-scoped; no mutable current-map global exists. Corridor floors omit center, while actual rooms retain it for scene painting/thresholds. Spatial initialize uses the configured spawn room and supplies collision-safe fallback spots for arbitrary configured IDs.

Example: const map=getMap({id:'stormbreak-annex',version:1}); const spatial=createSpatialWorld(map.geometry); spatial.navigation(actor,{x:430,y:230},serverNow,state) proposes a physical route or null. This exact geometry is used by root authority, rendering and local demo navigation. Never send a model hidden state just to compute a path.

## State and original entry points

createMatch({id,tactical:true,map:{id,version},mode,roster,saboteurCount,humanPlayerIds,seed?,now,config,beaconRules}) creates match schema4 with worldVersion1, beaconVersion1, tacticalVersion1, map and preset:{id:'tactical',version:1}. seed is a labeled fixture option; production still uses secure role randomness. New room schema3 stores normalized lobby, map/preset and bounded settings receipts. Constructors without tactical keep the previous schemas. Normal loadConfig enables tactical; direct test constructors can still explicitly exercise legacy modes. LANTERN_MAP chooses only new lobbies' initial map.

Root server/engine/index.mjs keeps createMatch, tick, applyAction, applyInput, getPlayerView, getReplay and getReplaySnapshots. It selects runtime/context from the saved map before initialization/task generation. Context remains {record,publicEvent,nearby,sees,stop,geometry}, now with the actual match geometry. Both reports and all interaction descriptors use actual visibility/distance. Do not replace ctx with a static default-map helper. New safe game fields are tacticalVersion/map/preset; game.rooms uses the actual layout. All prior auth, origin/body/rate limits, queues, input leases and provider reservations stay in the same application path.

After settling to a systems deadline and calling advanceSystems, root calls spatial.invalidateRoutes(state,at,record). It validates the remaining accepted polyline against current doors and stops an invalid route with a motion record reason route_invalidated at that exact boundary. It returns a changed boolean, never moves an actor or changes input/action receipt IDs. Manual input and still-valid routes are preserved. The ordinary next navigation proposal is validated again.

## Lobby map adapter

POST /api/rooms/:roomId/settings accepts exactly {id,mapId,expectedRevision}. It requires that room's authenticated host cookie and configured origin, and runs in the same room queue as Start. A fresh selection after start rejects. Retrying a retained identical accepted ID after Start stays inert; different contents under the same ID conflict. Retained denied revisions stay denied. The map-only adapter does not allocate seats or create another lobby system.

Room view adds map:{id,version}, preset, availableMaps and settingsRevision for schema3 rooms. Private room.settings={revision,requests} retains at most64 request receipts without evicting IDs into eligibility. Each receipt contains {id,fingerprint,accepted,revision,error?}. The entire ledger remains server-side. Store validation binds room/match/map/version/preset/tasks/positions/notes/snapshots and protects unsupported forward versions without rewriting user files.

createWorldExperience(host,callbacks) adds async callbacks.settings(mapId); all existing action/input/start/leave/loadReplay callbacks stay unchanged. public/world/lobby-map.mjs exports createLobbyMapSelector({id,settings,change}), returning node/update/pending/suspend/dispose. It displays server-confirmed values, honors host/pending/connection state and cancels obsolete feedback. Root supplies a fresh ID and current expectedRevision; epoch/generation/revision guards prevent late responses or retained retries from rolling back a newer map or replacing a started match. Do not write selection straight into local state.

## Systems and evidence

Existing SYSTEM_ACTIONS, initialization/deadline/advance/phase/validate/apply/hints/view exports remain. Schema4 tactical systems.version2 has factionCooldowns.saboteur:{criticalAt,auxiliaryAt}, actor cooldowns:{ventAt}, and doors:{id,closed,status,startedAt,closeAt,deadlineAt}. Door status is open/pending/closed/jammed. shared/tactical.mjs exports TACTICAL_PRESET and DEFAULT_TACTICAL_BEACON_RULES; the default tactical door duration25s differs from legacy12s. Rules/clocks are persisted per match, not read from ambient global state on restore. The public view exposes only current physical system status, safe critical progress and the viewer's permitted clocks; no raw faction clock table, repairer IDs or secret actor destinations are sent.

systemSabotage{kind,targetId}, systemRepair{systemId,siteId}, vent{entryId,exitId}, investigate{deviceId} and deviceCancel{} retain the shared/beacon.mjs action fields and engine receipt envelope {id,type,...fields}. TargetId beacon is the canonical non-door system target on both locations; door IDs and all site/hatch/device IDs come from that map's fixtures. It is not a map override. Every actor/role/proximity/link/cooldown is validated server-side. Existing taskService remains the authority for task/taskInteract progress; repairs use bounded validated site contributions. Future ability permissions must join the existing trusted registry, not client role/faction claims.

Investigation sessions and observations retain original IDs/types/times; schema4 adds exact map:{id,version}. An observation is {id,deviceId,kind,at,map,provenance:{type:'device',ownerId},data}. Camera data.frames entries are {cameraId,field:{origin,radius,facingRad,fovRad},limited,players:[{id,position}]}; occupancy data.rooms is [{roomId,count}]; vitals data.players is [{id,status}]. Legacy schema3 record shapes remain valid. Access is reevaluated before sampling and when projecting a pending session. Actual source time, historical scope and current access/availability are separate. Future decoys/claims must not be recorded as source observations.

## Existing AI and Group2 seams

server/features/strategy/index.mjs keeps createGoalRegistry, localGoals, localNavigationIntent and deviceFacts, and adds localRoute(view,target). localRoute uses immutable map geometry plus only public door states and the actor's permitted position; it never receives raw match state. Goals are still proposals. The existing demo controller uses bounded investigation attempts, personal passages and ordinary validated actions, and preserves per-character memory/budgets. deviceFacts keeps up to three owner samples, up to24 room rows (all eight Annex rooms), up to eight camera fields/six observed IDs and twelve vitals IDs; tactical map identity is retained. Council names/eyewitness room checks use view.rooms. The actual provider request additionally includes public map/room names, not hidden coordinates, roles or private memories belonging to others.

Existing server/public features task, strategy, lobby, abilities, panels and replay directories remain reserved for Group2. Field-note is still a working baseline ability; no ghost role or public multiplayer allocator is invented. Replay start records and five-second sampled snapshots carry tactical map identity. The existing ended-only authenticated replay route adds map/preset and snapshots; pre-end access returns409. A new phase/room/map must dispose or invalidate old UI work; historical samples keep their original map/time rather than being repainted as fresh telemetry.

See NEXT_FEATURE_INTERFACES.md for the retained registration exports and examples; this document supplies the additional schema4/map context. Group2 should use current merged main or an explicitly approved integration pin and preserve the original saved-format versions. Tests are ordinary npm test plus real-browser npm run test:browser, npm run test:tactical-browser and the explicit legacy gates; syntax preparation alone is not gameplay verification.
