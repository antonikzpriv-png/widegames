# Tactical systems implementation

Foundation2658044; own systems modules and tactical-systems tests only. Existing schema3 systems.version1 retains per-actor clocks, immediate12s door closures and byte-compatible state/view shapes. Absent map resolves original immutable Beacon. All fixture lookups resolve getMap(state.map).fixtures and descriptor geometry; no mutable current-map singleton.

Schema4/tacticalVersion1 requires exact map and preset:{id:'tactical',version:1}; systems.version2 adds factionCooldowns:{saboteur:{criticalAt,auxiliaryAt}} and personal cooldowns:{actor:{ventAt}}. Critical starts charge the shared faction clock and each saboteur's legacy sabotageAt display; auxiliary starts charge the separate shared clock. Passage charge remains personal through travel+cooldown, never refunded. Owner projection composes shared sabotage clocks only for saboteurs; other actors and spectators receive no faction dictionary. One critical, one lights and one communications effect may coexist with at most two occupied door slots (pending/closed/jammed). Custom short auxiliary cooldowns in tests exercise the upper bound; default20s auxiliary cooldown and12s closed duration usually permit fewer simultaneous doors.

A v2 door stores {id,closed,status,startedAt,closeAt,deadlineAt}. Status is open/pending/closed/jammed. A sabotage reserves a slot and publicly warns for exactly TACTICAL_PRESET.doorGraceMs=1000. Physics sees closed:false during warning. At closeAt, any non-transit keeper's body circle touching the door rectangle (including tangency and undiscovered dead keepers) prevents closure: the door becomes jammed but stays open. No displacement, stopped occupant, occupant IDs/counts or permission/hint occupancy oracle. The single anonymous jam status is public. No repeated closure attempts occur; leaving the threshold does not cause surprise closure. The scheduled deadline is start+grace+doorDuration (default13s total), which clears pending/closed/jammed state and restores a slot. This bounds scheduling to one closure and one expiry, with no jam retry loop. A living local keeper of either faction can cancel a pending warning, reopen a closed door or reset a jam from either exterior panel; no cooldown refund. Door repair at/after expiry rejects. Council cancels all door states before closure at an equal phase boundary. Critical/maximum/phase precedence stays root-owned.

Core integration: immutable descriptor doors and systems.doors[].closed must govern collision, LOS, routes and AI navigation. Coordinator must settle positions at the exact closure boundary before advanceSystems; a delayed standalone module call cannot reconstruct earlier moving positions. Core must invalidate/recheck accepted routes when closed changes, permit alternate paths and restore legality on reopening. Systems never changes an occupant position or owns Core path caches. Client should render pending closeAt and jammed status from safe doors. Root must set schemaVersion4/tacticalVersion1/map/preset before initializeSystems, and invoke phase/death hooks with its chronological loop. Systems signatures and action fields are unchanged; root owns serialized action receipts and duplicate-ID replay.

Critical power/flood keep canonical sabotage and two distinct local living crew/site contributions. Meetings retain auxiliary/critical original clocks, cancel travel in place and reopen doors. Death cancels travel without teleport/refund; end/pause clear auxiliary and door/transit timers. Passage entry/exit evidence remains typed, actor/local-witness-only and excludes the remote endpoint. Safe views omit raw transit, recipients and critical contributors; snapshots validate exact v1/v2 shapes, immutable map/version/fixtures, topology, durations, bounded clocks/door slots, actor ownership and canonical repairs.

Initial tests use seeded actual legacy match construction, explicit two-saboteur module fixtures, real immutable map geometry and injected documented context. They qualify systems lifecycle/validation, not root schema4/HTTP/store/browser integration or final Core path invalidation. Annex is not yet in foundation2658044; Beacon is exercised now, and actual Annex fixture qualification remains pending Core delivery. No provider/browser/install/deployment/main/push or other owner edits.
