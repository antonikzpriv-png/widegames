﻿# Room service and persistence

For the current configurable room schema, routes, ownership, socket re-resolution, rematch fences and archive limits, see [Multiplayer lobbies and rematches](MULTIPLAYER.md). The original fixed-six contracts below describe historical room compatibility where they differ.

`createGameServer(config)` returns an unstarted native HTTP server, a private rooms map and asynchronous idempotent `close()`. Engine and AI modules use their stable contract imports. The optional second argument accepts `engine`, `aiController`, `store` and `dailyBudget` for fault tests. Configuration may supply a `now()` clock. Production keys and rules come only from server configuration.

POST routes require JSON objects and the exact configured public Origin. All API responses disable caching; foreign Origin and cross-site fetches are rejected, including socket upgrades. No CORS permission is granted. API query parameters are rejected except the completed replay match selector documented below. Bodies are capped at 8 KiB. The service trusts the actual socket address for limits, never forwarded headers.

Each room has an independent 256-bit HttpOnly, SameSite=Strict cookie scoped to `/api/rooms/:id`, with Secure on HTTPS. Only its SHA-256 digest is persisted. Creating a human room assigns the host p1. Empty join requests preserve spectator defaults; configurable lobbies support explicit authenticated seat claims before start. Joining again with a valid cookie preserves that identity and seat. Other room cookies cannot authenticate a room. A lost human cookie cannot be replaced or reassigned. Configurable rooms persist normalized keeper names and palette colors with stable numbered badges.

Create, join, start and action return the safe room envelope directly. Replay retains `{roomId,replay}` and adds the completed match identity, reconstruction metadata and safe AI summary only after the engine ends the match. WebSocket upgrades require the same cookie and exact Origin and immediately receive `{type:'state',room}`; subsequent committed changes are broadcast using each connection's own engine view. Client messages close the socket; actions use HTTP. Hosts, visitors and AI each receive the engine's corresponding safe view. AI public metadata uses an explicit allowlist; context and token digests stay private.

Limits are bounded per process: configured room count; 128 identities per room; 8 creates, 40 joins, 30 socket attempts and 180 writes per socket address per minute; 60 writes per identity per minute; 600 total API requests per address per minute. There are at most 100 open WebSockets and four per identity. Authenticated seated humans divide their address-level request/write/input charge by the current number of non-revoked human seats. This supports a full group on one network address without raising per-identity movement or action limits; spectators and anonymous requests retain full weight. Single-human address limits remain unchanged. The limiter table is capped at 10,000 buckets. Slow socket readers are closed at 256 KiB buffered output. Sockets receive ping/pong health checks. Lobby, ended and paused rooms expire after `roomTtlMs` without a persisted update. Active matches continue regardless of connected browsers; no bot takes over an active human seat.

Every room has one mutation queue. Start IDs, engine action IDs, engine deadlines, identities and private `aiContext` survive restart. Mutations save before replacing the in-memory state or broadcasting. JSON files are size and shape checked, temporary files are exclusive and private, and writes fsync the file before atomic rename. Invalid room files are moved to uniquely named quarantine files. An engine read failure on restored state stops startup. Missing or unreadable budget ledgers fail according to the manager-owned budget module. An exclusive process lock prevents two room services from using one data directory concurrently; a lock from a provably dead PID is reclaimed. Use a single process and local persistent disk. Atomic file replacement does not provide distributed storage or a guarantee against every filesystem/power-loss behavior.

AI decisions use one in-flight decision per room, choose actors fairly by next eligible time, and run outside the mutation queue so deadlines and HTTP actions continue during provider latency. Decisions receive only the actor view, public character and a cloned private context. The awaited `commitReservation({id,amountUsd})` callback first commits that context, then calls the durable deployment budget using a room-prefixed reservation ID. Either error rejects the callback before provider send. Each retry must invoke this callback again. Conservative reservations are never refunded after uncertain sends. Returned proposals are revalidated by the engine against the current state. Unhandled AI/storage errors pause AI with a safe notice; gameplay deadlines still run. Closing aborts pending decisions, clears timers, terminates sockets, drains operations and releases the storage lock.

Checks use no provider calls. Run `node --test tests/transport-service.test.mjs` after integrating the engine/AI modules, and `npm run check`. To test against sibling builders read-only before integration, set `TRANSPORT_TEST_ENGINE` and `TRANSPORT_TEST_AI` to their module file URLs. `TRANSPORT_TEST_TEMP` can select an existing temporary parent directory. Tests cover seat isolation, spectator redaction, socket Origin checks, duplicate start/action IDs across restart, unattended deadlines, expiry, every-attempt reservation ordering, both reservation failure boundaries, malformed storage, single-writer exclusion, real demo completion/replay and shutdown.

Stale process-lock recovery is serialized by the separate `service.lock.recovery` file, acquired with exclusive creation. Every startup and normal close holds that claim while inspecting, creating or deleting `service.lock`. Recovery reads the current primary lock inside the claim, requires a valid PID and token, proves the PID absent using the operating system, then rereads the same ownership and probes again immediately before unlinking. A second contender cannot delete the first contender's newly created live lock. Claim and primary release each require the recorded PID and token to match; foreign replacement locks are preserved and reported as errors. Concurrent close calls share one operation, and close can retry a transient claim conflict.

A preexisting recovery claim blocks startup even if its PID is dead, its contents are malformed, or the primary lock is absent. Automatically reclaiming this second lock would recreate the original race. Failed claim/primary initialization also leaves evidence in place. Operators must preserve both lock files and establish that all game/recovery processes have stopped before repairing ambiguous storage; normal startup never silently deletes a foreign claim or live-PID lock. The protocol assumes cooperating services and local exclusive-create filesystem semantics; arbitrary external modification of lock files is outside that protocol and produces ownership errors.

Run `node --test tests/transport-lock-process.test.mjs` independently of engine and AI integration. It retains the vulnerable 0979ea9 lock protocol as an explicit negative control. Two real children share a labelled lock from an actually exited process; IPC pauses stale reads and holds every successful writer until the parent acknowledges release. The old protocol admits two held writers, while the fixed protocol admits exactly one. Additional controls cover live replacements before and during recovery, foreign primary/claim release, dead or malformed recovery claims, invalid primary metadata and concurrent/retried close. Test children and fixture files remain under the configured D: temporary parent. The separate manager inspection and findings are recorded in `TRANSPORT-MANAGER-AUDIT.md`.
# Spatial replay extension

Completed-match replay responses retain `{roomId,replay}` and add `matchId`, validated reconstruction metadata and the allowlisted AI completion summary. An optional single `matchId` query must match the completed match in the authenticated room; other API routes still reject queries. Unfinished/paused replay remains denied, cross-room cookies remain unauthorized, and unavailable archived generations return 404. No archive/rematch facility is introduced. See [SPATIAL-REPLAY.md](SPATIAL-REPLAY.md) for coverage, privacy, lifecycle and validation details. Existing historical transport evidence below is preserved.

## Interactive all-AI observation

Authenticated seatless viewers of a walking-world **all-AI** room receive an additive `game.inspection` object in both HTTP and WebSocket views. It identifies the exact match and contains bounded per-agent roles, task progress, abilities/cooldowns, positions/destinations, recent accepted action labels and public claims. The current activity label describes authoritative movement or match phase; it is not a report of model thoughts. A live strategic controller may also supply an optional selected-plan summary: only a known goal, validated game-object IDs and recorded selection/expiry times are projected. It is explicitly labeled as the last selected plan, which may no longer be current. No free-form model text is read. Wrong-match, expired, inactive-phase, dead-agent, completed-task and demo/fallback plans are omitted. Inspection never copies raw AI contexts, private reasoning, unrestricted memories, provider errors, keys or fallen chat. Task challenge solutions and full action payloads are not included. Recent action lookup scans at most the latest 256 retained records once, and returns at most six actions and three public claims per agent.

Human-room players and their spectators receive no inspection object. The engine's player/AI view remains unchanged: other roles stay hidden before completion, and no inspection data enters a model request. The observer remains unable to send actions or movement. Cross-room cookies cannot authorize inspection; live and paused full replay remain unavailable. Room/match identity is carried by the ordinary authenticated envelope.

The mutation queue and durable-before-publish ordering remain intact. Hot tick/input/action paths copy the room envelope while retaining the engine's independently owned replacement state, avoiding a second clone of the entire retained replay. Input keeps its defensive engine boundary copy for fault-injected engines. AI scheduling checks authoritative actor eligibility locally and constructs a full redacted view only for the selected actor, rather than doing that work for every candidate on each tick.

Run `node --test tests/spectator-inspection.test.mjs tests/world-transport-envelope.test.mjs tests/transport-terminal-ai.test.mjs` for inspection authorization/privacy, defensive projection copies, selected-actor scheduling, input fault isolation and terminal AI reservation regressions.

Current observer privacy boundary: default viewers receive no `game.inspection`. An authenticated unseated identity may explicitly toggle `/inspection` with `{enabled, generation}` only for an active WATCH room with no human actors. Consent is private to that identity, re-resolved on each HTTP/WS projection, and cleared by rematch. The pure projection helper also refuses human-containing states. A WATCH-mode room with claimed human seats never grants inspection.
