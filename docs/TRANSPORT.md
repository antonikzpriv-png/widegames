# Room service and persistence

`createGameServer(config)` returns an unstarted native HTTP server, a private rooms map and asynchronous idempotent `close()`. Engine and AI modules use their stable contract imports. The optional second argument accepts `engine`, `aiController`, `store` and `dailyBudget` for fault tests. Configuration may supply a `now()` clock. Production keys and rules come only from server configuration.

POST routes require JSON objects and the exact configured public Origin. All API responses disable caching; foreign Origin and cross-site fetches are rejected, including socket upgrades. No CORS permission is granted. API query parameters are rejected. Bodies are capped at 8 KiB. The service trusts the actual socket address for limits, never forwarded headers.

Each room has an independent 256-bit HttpOnly, SameSite=Strict cookie scoped to `/api/rooms/:id`, with Secure on HTTPS. Only its SHA-256 digest is persisted. Creating a human room assigns the host p1; visitors always receive spectator identities. Joining again with a valid cookie preserves that identity and seat. Other room cookies cannot authenticate a room. A lost human cookie cannot be replaced or reassigned. The optional room name is validated but not displayed or persisted; characters retain their established names.

Create, join, start and action return the safe room envelope directly. Replay returns `{roomId,replay}` only after the engine ends the match. WebSocket upgrades require the same cookie and exact Origin and immediately receive `{type:'state',room}`; subsequent committed changes are broadcast using each connection's own engine view. Client messages close the socket; actions use HTTP. Hosts, visitors and AI each receive the engine's corresponding safe view. AI public metadata uses an explicit allowlist; context and token digests stay private.

Limits are bounded per process: configured room count; 128 identities per room; 8 creates, 40 joins, 30 socket attempts and 180 writes per socket address per minute; 60 writes per identity per minute; 600 total API requests per address per minute. There are at most 100 open WebSockets and four per identity. The limiter table is capped at 10,000 buckets. Slow socket readers are closed at 256 KiB buffered output. Sockets receive ping/pong health checks. Lobby, ended and paused rooms expire after `roomTtlMs` without a persisted update. Active matches continue regardless of connected browsers; no bot takes over human p1.

Every room has one mutation queue. Start IDs, engine action IDs, engine deadlines, identities and private `aiContext` survive restart. Mutations save before replacing the in-memory state or broadcasting. JSON files are size and shape checked, temporary files are exclusive and private, and writes fsync the file before atomic rename. Invalid room files are moved to uniquely named quarantine files. An engine read failure on restored state stops startup. Missing or unreadable budget ledgers fail according to the manager-owned budget module. An exclusive process lock prevents two room services from using one data directory concurrently; a lock from a provably dead PID is reclaimed. Use a single process and local persistent disk. Atomic file replacement does not provide distributed storage or a guarantee against every filesystem/power-loss behavior.

AI decisions use one in-flight decision per room, choose actors fairly by next eligible time, and run outside the mutation queue so deadlines and HTTP actions continue during provider latency. Decisions receive only the actor view, public character and a cloned private context. The awaited `commitReservation({id,amountUsd})` callback first commits that context, then calls the durable deployment budget using a room-prefixed reservation ID. Either error rejects the callback before provider send. Each retry must invoke this callback again. Conservative reservations are never refunded after uncertain sends. Returned proposals are revalidated by the engine against the current state. Unhandled AI/storage errors pause AI with a safe notice; gameplay deadlines still run. Closing aborts pending decisions, clears timers, terminates sockets, drains operations and releases the storage lock.

Checks use no provider calls. Run `node --test tests/transport-service.test.mjs` after integrating the engine/AI modules, and `npm run check`. To test against sibling builders read-only before integration, set `TRANSPORT_TEST_ENGINE` and `TRANSPORT_TEST_AI` to their module file URLs. `TRANSPORT_TEST_TEMP` can select an existing temporary parent directory. Tests cover seat isolation, spectator redaction, socket Origin checks, duplicate start/action IDs across restart, unattended deadlines, expiry, every-attempt reservation ordering, both reservation failure boundaries, malformed storage, single-writer exclusion, real demo completion/replay and shutdown.
