# World movement transport

Milestone: authenticated HTTP input boundary. `POST /api/rooms/:id/input` accepts exactly `{seq,dx,dy}`. Sequence must be a positive safe integer; directions are integers in -1..1, including a zero-vector stop. Actor identity comes exclusively from the same-room human p1 cookie. Spectators, other room cookies and invalid origins are denied. Existing JSON/body limit remains 8KiB. Input has separate per-address and per-identity 600/minute counters; it consumes neither the 60/minute discrete identity allowance nor the discrete write bucket. Every input request still consumes the original overall 600/minute HTTP ceiling.

Input executes inside the existing room mutation queue, receives a clone of current state, validates the engine result before persistence, persists changed results before broadcasting, and replies only with the engine's permitted player view. Sequence acceptance/duplicates/staleness belong to authoritative `engine.applyInput`; inert duplicate results do not write or broadcast. Changed denial state is retained before returning its safe error. Start passes `world: config.worldMode===true`; direct configs without that explicit flag remain legacy. The transport does not manufacture `worldVersion`, coordinates or roles in views. WebSocket messages remain receive-only; inputs use HTTP.

`tests/world-transport-envelope.test.mjs` explicitly injects only `applyInput` policy and legacy initialization to isolate transport shape/auth/quota/serialization/restart behavior before the new Core schema is available. It uses real HTTP, cookies, room/store, real WebSocket views and no provider activity. Its private `_transportTestInput` metadata is a labelled test-only sequence checkpoint, not production world state. The memory-store variants isolate rate limits without hundreds of fsync operations. This milestone does not claim world movement, proximity, lease expiry or schema2 validation qualification; those require the imminent shared/Core contract and a subsequent focused commit. Existing user data and other worktrees are untouched.
